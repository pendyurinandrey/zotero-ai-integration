# Troubleshooting

## Запрос к `http://127.0.0.1:11434` не отвечает

Ollama не запущен. Запустите `brew services start ollama` или `ollama serve`.

## Claude спрашивает разрешение на каждый вызов поиска

Не принято доверие к папке (trust dialog), поэтому разрешения из `.claude/settings.json` игнорируются. Откройте Claude Code в папке репозитория и подтвердите доверие.

## `claude mcp list` не показывает `zotero` или показывает ошибку

`claude mcp add` выполняется для папки, где вы его запустили (область `local`). Выполните команду из папки репозитория. Если сервер в состоянии ошибки, проверьте `zotero-mcp version`.

## В папке предмета Claude не видит skill или MCP-сервер zotero

Проверьте, что папка подключена скриптом `scripts/new-subject.sh` ([docs/subjects.md](subjects.md)): должны быть `.claude/skills/zotero-library`, `.claude/settings.json` и `.mcp.json`. Симлинки «висят», если репозиторий перенесли; удалите их и запустите скрипт заново. Подключение `.mcp.json` нужно один раз подтвердить в Claude Code (`claude mcp list` показывает `Pending approval`, пока этого не сделано).

## Поиск по коллекции через MCP даёт ошибку `filters ... Input should be a valid string`

Это известное ограничение: инструмент `zotero_semantic_search` принимает фильтр только как словарь со строковыми значениями, а для ограничения набором статей нужен вложенный фильтр `{"$in": [...]}`. Claude Code не умеет передать его через MCP. Поэтому поиск внутри коллекции выполняется скриптом `scripts/search-in-collection.sh` (он вызывает `zotero-cli`, где фильтр передаётся аргументом командной строки). Подробнее: [docs/clients/claude-code.md](clients/claude-code.md).

## `zotero_semantic_search` падает с `Error finding id`

Полный текст ошибки: `Semantic search error: Error executing plan: Internal error: Error finding id`. Она появляется на любых запросах (в том числе по старым темам) после того, как индекс обновили, а сессия Claude Code была открыта раньше.

**Причина.** MCP-сервер `zotero` в сессии открывает индекс один раз при запуске и держит его состояние в памяти. Chroma не синхронизирует между собой процессы, работающие с одним индексом на диске. Когда другой процесс (`zotero-mcp update-db`) добавляет или переиндексирует записи, уже работающий сервер не видит новых записей, и запросы к нему падают. Сам индекс при этом цел: свежий процесс читает его без ошибок. Ошибка воспроизведена на копии индекса: читатель открыл индекс, другой процесс добавил в него 14 фрагментов, запрос читателя с фильтром по новой записи упал с этой ошибкой.

**Что делать.** Перезапустите MCP-сервер в сессии: в Claude Code `/mcp`, выберите `zotero`, затем Reconnect (или откройте новую сессию). Правило: после каждого `zotero-mcp update-db` перезапускайте MCP-сервер во всех открытых сессиях, где работаете с Zotero.

Пока сервер не перезапущен, поиск скриптами `scripts/search-passages.sh` и `scripts/search-in-collection.sh` работает: они открывают индекс заново при каждом запуске. Если ошибка не уходит и после перезапуска, проверьте, что `update-db` не выполняется прямо сейчас (файл `~/.config/zotero-mcp/update.lock`), подождите его завершения и проверьте поиск ещё раз.

## Книга или статья не находится в поиске по смыслу

Запустите `scripts/check-text-layer.sh` (при необходимости с `--collection "Название"`) и посмотрите, что он пишет об этой записи:
- **«НЕ В ИНДЕКСЕ»** — запись добавлена после последней индексации: `zotero-mcp update-db --fulltext`.
- **«PDF без текстового слоя»** или **«с текстом не на всех страницах»** — нужен OCR, см. [шаг 6](setup/06-ocr.md).
- **«PDF без родительской записи»** — файл лежит в Zotero отдельным вложением, индексатор его пропускает: создайте запись вручную и перетащите в неё файл ([как](setup/06-ocr.md#файл-без-родительской-записи)).
- **«Без PDF-вложения»** — в поиске только метаданные записи.
