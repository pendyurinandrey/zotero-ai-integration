# 2. Zotero

Нужен Zotero 10. Поиск и чтение библиотеки **не требуют** никаких настроек Zotero: сервер читает базу `zotero.sqlite` напрямую (точнее, её копию вместе с журналом `-wal`: Zotero может быть и запущен, и закрыт). Облако Zotero и API-ключ не нужны.

Проверено 2026-10-03 на Zotero 10.0.5: при **выключенной** опции «Allow other applications on this computer to communicate with Zotero» (запросы к локальному API отвечают `403`) и при **закрытом Zotero** все читающие инструменты сервера работают: поиск по смыслу, обычный поиск, список коллекций и их статей, метаданные, полный текст, чтение страниц PDF, вложения, теги, аннотации, обновление индекса. Скрипты репозитория тоже работают.

Поэтому для сценария «искать и читать» эту опцию включать не нужно.

## Когда нужен локальный API (только для записи)

Опция **«Allow other applications on this computer to communicate with Zotero»** (в настройках Zotero, раздел Advanced) нужна, только если вы хотите, чтобы нейросеть **писала** в библиотеку (теги, заметки, перенос в коллекции, добавление статей). В Zotero 10 запись идёт через локальный API и требует разрешения: при первой попытке Zotero покажет запрос (разово или постоянно).

Важное ограничение: адрес записи в сервере жёстко задан как `127.0.0.1:23119` (порт по умолчанию, который использует и сама библиотека `pyzotero`). Если вы изменили порт Zotero, запись через сервер работать не будет, а чтение продолжит работать.

Проверка (если включали опцию), порт по умолчанию 23119:

```bash
curl -s -H "Zotero-API-Version: 3" "http://127.0.0.1:23119/api/users/0/items?limit=2&format=json"
```

Ответ `403 Forbidden` означает, что опция выключена; для чтения это нормально.

Если вам нужен только поиск, опцию включать и разрешение на запись давать не нужно.
