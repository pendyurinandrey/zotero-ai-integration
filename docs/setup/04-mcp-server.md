# 4. MCP-сервер zotero-mcp

Единая точка входа в Zotero для нейросетей: [54yyyu/zotero-mcp](https://github.com/54yyyu/zotero-mcp) (лицензия MIT). Он читает библиотеку Zotero, строит индекс для поиска по смыслу (через Ollama и `bge-m3`) и отдаёт инструменты нейросети по протоколу MCP.

## Установка

Ставим через `uv tool`, в собственное окружение, с явно заданным Python (не 3.14). Версия закреплена (проверено на 0.17.0):

```bash
uv tool install --python 3.13 "zotero-mcp-server[semantic,pdf]==0.17.0"
```

Скачивается около 1,2 ГБ (вместе с `torch`). Исполняемые файлы кладутся в `~/.local/bin`. Если команда `zotero-mcp` не находится, добавьте эту папку в `PATH`:

```bash
uv tool update-shell
```

(команда правит конфиг вашего шелла; после неё откройте новый терминал).

### Обновление и откат

- Если у вас уже стоит другая версия `zotero-mcp-server`, добавьте в команду `--force`. После переустановки перезапустите MCP-сервер во всех открытых сессиях Claude Code (`/mcp` → `zotero` → Reconnect): уже запущенный сервер продолжает работать со старой установкой и старым состоянием индекса.
- До 0.17.0 мы использовали форк [pendyurinandrey/zotero-mcp](https://github.com/pendyurinandrey/zotero-mcp) (0.13.1 плюс настройка ширины цитаты `semantic_search.snippet_width`). Предложение в оригинал ([54yyyu/zotero-mcp#626](https://github.com/54yyyu/zotero-mcp/pull/626)) закрыто как устаревшее: в 0.16 появился параметр `full_passage` у `zotero_semantic_search`, который решает ту же задачу (см. ниже). Откат на форк: `uv tool install --python 3.13 --force "zotero-mcp-server[semantic,pdf] @ git+https://github.com/pendyurinandrey/zotero-mcp.git@v0.13.1-snippet-width"` (ключ `snippet_width` в конфиге нужно вернуть).
- Индекс, построенный 0.13.1, 0.17.0 читает без пересборки (схема индекса осталась 3). В 0.17 индекс при желании можно разделить на две коллекции (`zotero-mcp migrate-index`, статьи отдельно от фрагментов); **наши скрипты** (`search-passages.sh`, `check-text-layer.sh`) читают коллекцию `zotero_library` целиком, и после миграции их нужно переделывать, поэтому миграцию не выполняем. В `zotero-mcp db-status` без миграции будет выведено пояснение про неё: это информация, а не ошибка.

## Проверка

```bash
zotero-mcp version
```

Должно вывести версию (мы проверяли на 0.17.0).

## Конфигурация поиска по смыслу

Создайте каталог и закройте его от других пользователей:

```bash
mkdir -p ~/.config/zotero-mcp
chmod 700 ~/.config/zotero-mcp
```

Затем создайте в нём файл `~/.config/zotero-mcp/config.json` (любым редактором или вставьте блок JSON ниже в команду `cat > ~/.config/zotero-mcp/config.json`) со следующим содержимым:

```json
{
  "semantic_search": {
    "embedding_model": "ollama",
    "embedding_config": {
      "model_name": "bge-m3",
      "timeout": 600,
      "request_batch_size": 16
    },
    "include_fulltext": true,
    "extraction": {
      "pdf_max_pages": 1000
    },
    "chunking": {
      "enabled": true,
      "chunk_size": 1500,
      "overlap": 200,
      "max_chunks_per_item": 3000
    }
  }
}
```

Зачем каждая настройка:

- `embedding_model: ollama` и `model_name: bge-m3` — многоязычные эмбеддинги через локальный Ollama (адрес по умолчанию `http://localhost:11434`).
- `chunking.enabled: true` — **обязательно**. Без него каждая статья превращается в один вектор, и поиск находит статью, но не место в ней, а длинные тексты обрезаются. С разбиением на фрагменты поиск возвращает конкретные отрывки для цитат.
- `chunk_size` и `overlap` — размер фрагмента и перекрытие, в символах.
- `max_chunks_per_item: 3000` — по умолчанию 20 фрагментов на документ (около 30 тысяч символов, то есть примерно 10 страниц), для книг этого мало. Учебник на 600 страниц это около 1000–1400 фрагментов, `.txt` на 1,5 МБ около 1400 (проверено).
- **Ширина цитаты.** По умолчанию сервер отдаёт цитату в окне около 320 символов, подобранном по совпадению слов запроса; при вопросе на одном языке к статьям на другом окно обычно берётся с начала фрагмента, и нужное место теряется. Чтобы получить фрагмент целиком (до 1500 символов), `zotero_semantic_search` нужно вызывать с `full_passage=true` (с 0.16; фрагменты одного ответа делят 15 000 символов, не меньше 400 на каждый). Это записано в skill `zotero-library`. У `zotero-cli` такого флага нет, а `scripts/search-passages.sh` читает индекс напрямую и ширину цитаты задаёт сам (`--max-chars`). Раньше для этого был ключ `snippet_width` форка; в 0.17.0 он ничего не значит и из конфига удалён.
- `pdf_max_pages: 1000` — по умолчанию читается только часть страниц PDF, для книг нужно больше.

Проверка, что конфиг подхвачен:

```bash
zotero-mcp db-status
```

В выводе должно быть `Embedding model: ollama` и `Passage chunking: enabled`.

## Как сервер подключается к Zotero

Режим `ZOTERO_LOCAL=true` (используется в конфиге MCP-клиента) читает библиотеку локально напрямую из `zotero.sqlite` (из копии вместе с журналом `-wal`). Для чтения локальный API Zotero и его адрес не нужны: проверено на Zotero 10.0.5 при выключенном API, см. [шаг 2](02-zotero.md).
