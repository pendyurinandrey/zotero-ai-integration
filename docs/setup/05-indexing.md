# 5. Индексация библиотеки

Индексация читает тексты PDF из Zotero, режет их на фрагменты, получает для каждого вектор от `bge-m3` (через Ollama) и складывает в локальную базу ChromaDB. После этого работает поиск по смыслу. Данные не покидают компьютер.

## Запуск

Перед запуском: Ollama должен быть запущен (Zotero не обязателен, база читается напрямую) (см. [шаг 2](02-zotero.md) и [шаг 3](03-ollama-and-model.md)), конфиг из [шага 4](04-mcp-server.md) на месте.

Первая (полная) индексация:

```bash
zotero-mcp update-db --fulltext --force-rebuild
```

`--fulltext` обязателен: без него индексируются только название, аннотация и теги. `--force-rebuild` нужен при первом запуске и при смене модели или настроек фрагментов.

Чтобы добавить в индекс новые статьи позже, достаточно:

```bash
zotero-mcp update-db --fulltext
```

## Проверка

```bash
zotero-mcp db-status
```

`Document count` — это число **фрагментов**, а не статей (статья даёт десятки фрагментов).

Пробный запрос:

```bash
zotero-cli search "ваш вопрос" --mode semantic --limit 3 --detail full
```

В ответе для каждой статьи есть:
- `Relevance` — оценка близости;
- `Location` — страница и номер фрагмента (например, `p. 82, passage 130/193`);
- `Matched Passage` — найденный отрывок текста, из которого делается цитата.

Запрос можно задавать на русском, статьи могут быть на английском (проверено, см. [шаг 3](03-ollama-and-model.md)).

## Результаты замера (тестовая библиотека)

- 15 статей, 921 фрагмент, 1 минута 25 секунд на индексацию.
- Одна запись без текстового вложения проиндексирована только по метаданным.

Для реальных коллекций (до 200 PDF, часть — книги) время будет заметно больше: замеры будут добавлены сюда.

## Когда и как обновлять индекс

Индекс — это снимок библиотеки на момент последнего обновления, Zotero сама его не обновляет:

- **Добавили статью или книгу в Zotero** — поиск по смыслу её не найдёт, пока индекс не обновлён. Обычный поиск по названию (`zotero_search_items`) найдёт сразу, он читает Zotero напрямую.
- **Удалили статью** — её фрагменты остаются в индексе до обновления.
- **Заменили PDF в записи** (например, после OCR) — нужно обновить индекс.

### Ручное обновление (по умолчанию)

```bash
zotero-mcp update-db --fulltext
```

Обновление **инкрементальное**: индексируются только новые и изменённые записи, удалённые убираются из индекса. Если менять нечего, команда отрабатывает за доли секунды. На тестовой статье (23 фрагмента) обновление заняло около 2 секунд. Большая книга занимает заметно дольше.

Помнить об обновлении не обязательно: `scripts/check-text-layer.sh` (его запускает Claude в начале сессии) сверяет библиотеку с индексом и пишет «НЕ В ИНДЕКСЕ» со списком статей и командой. Но пока вы не открыли новую сессию и не выполнили команду, новые статьи в смысловом поиске не видны. Чтобы убрать «ручную» часть совсем, включите автообновление.

### Автообновление

В `~/.config/zotero-mcp/config.json`:

```json
"semantic_search": {
  "update_config": {
    "auto_update": true,
    "update_frequency": "daily"
  }
}
```

`update_frequency`: `manual` (никогда), `startup` (при каждом поиске, если с прошлой проверки прошло больше минуты), `daily`, `every_3` (раз в 3 дня; число любое).

Как это работает: перед смысловым поиском сервер проверяет, пора ли обновляться, и если да, запускает обновление **в фоне**. Поэтому первый поиск после добавления статьи всё ещё идёт по старому индексу, а следующий уже по новому.

Проверено 2026-10-03 в изолированной копии (индекс и база Zotero скопированы, настоящая библиотека не затрагивалась; «новая» статья имитировалась удалением её из индекса копии):

| Режим | Результат |
|---|---|
| `auto_update: true`, `startup` | первый поиск статью не нашёл; через ~10 секунд фоновое обновление добавило 23 фрагмента (855 → 878), поиск нашёл её |
| `auto_update: false`, `manual` | за 16 секунд (4 поиска) статья не появилась; `zotero-mcp update-db --fulltext` добавил её за 2 секунды |

Оговорки:
- Проверялась имитация новой статьи, а не реальное добавление записи в Zotero.
- Фоновая индексация использует Ollama (он должен быть запущен) и нагружает процессор. Для больших книг это может занять минуты, и если сессия закончится раньше, достроит следующее обновление.
- Для первой большой индексации реальной коллекции лучше использовать ручной режим и смотреть за ходом; автообновление включать после.

## Записи без текста

Отдельно: в индекс попадают только статьи и книги. PDF, лежащий в Zotero **отдельным вложением без родительской записи**, не индексируется вовсе (см. [шаг 6](06-ocr.md#файл-без-родительской-записи)).

Если у PDF нет текстового слоя (скан), в индекс попадут только метаданные. Что делать со сканами, описано в [шаге 6](06-ocr.md).
