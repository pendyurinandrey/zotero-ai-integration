# 6. OCR для PDF без текстового слоя

Поиск работает по тексту. У отсканированного PDF текста нет, только картинки страниц, и индексатор запишет такую статью в индекс по метаданным (название, аннотация), а её содержимое найти будет нельзя. Поэтому сканы нужно распознать **до** добавления в Zotero.

## Рекомендуемый порядок

1. Прогнать PDF через `ocrmypdf` (ниже).
2. Добавить в Zotero уже **распознанный** файл. Исходный скан в библиотеку не добавлять, иначе в ней останется дубликат без текста. Убедиться, что у добавленного файла появилась **родительская запись** (статья или книга), см. [ниже](#файл-без-родительской-записи).
3. Обновить индекс: `zotero-mcp update-db --fulltext` ([шаг 5](05-indexing.md)).

## Установка ocrmypdf

Подробно: [github.com/ocrmypdf/ocrmypdf](https://github.com/ocrmypdf/ocrmypdf). На macOS:

```bash
brew install ocrmypdf
```

Вместе с ним ставится Tesseract, но только с английским (`eng`). Для русского нужен дополнительный пакет (скачивает около 700 МБ данных для 160 языков):

```bash
brew install tesseract-lang
tesseract --list-langs   # в списке должен быть rus
```

## Команда

```bash
ocrmypdf -l rus+eng --skip-text скан.pdf скан-распознанный.pdf
```

`-l rus+eng` — языки документа (для только английских статей достаточно `-l eng`). `--skip-text` — **всегда добавляйте**, причина ниже.

**Язык нужно указывать правильно.** Если не передать `-l rus`, русский скан распознается как мусор из латинских символов, а ocrmypdf при этом завершится успешно (код 0) и никаких ошибок не покажет. Проверено на тестовом скане русского текста:

| Параметр | Сходство распознанного текста с исходным (по страницам) |
|---|---|
| `-l rus+eng` | 100%, 100%, 100% (включая английскую фразу внутри русской страницы) |
| `-l eng` | 3%, 15%, 43% (например, «Выводы Смена карьеры» превратилось в «BsiBobl Cena kapbepbI») |

Тест сделан на чистом искусственном скане (текст отрисован и переведён в картинку, 200 dpi). На реальных сканах (наклон, пятна, старый шрифт) точность будет ниже, поэтому первые файлы стоит проверить глазами: выделите текст в распознанном PDF или откройте результат поиска.

## Что делает ocrmypdf, если в PDF уже есть текст

Проверено на ocrmypdf 17.13.0 (языки `eng`) на четырёх случаях:

| Случай | Без флагов | `--skip-text` |
|---|---|---|
| Все страницы — картинки, текста нет | Распознаёт все страницы. Выход 0. | То же. |
| Весь PDF с нормальным текстом | **Прерывается** с ошибкой `PriorOcrFoundError: page 1 already has text!`, код выхода 6, файл не создаётся | Ничего не меняет, копирует файл. Выход 0. |
| Часть страниц — картинки, часть с текстом | **Прерывается** с той же ошибкой, файл не создаётся | Распознаёт только страницы без текста, остальные оставляет как есть. Выход 0. |
| Скан, в который уже встроен текст (старый OCR) | **Прерывается** с той же ошибкой | Оставляет существующий текст, ничего не делает. Выход 0. |

Вывод: без `--skip-text` команда на любом файле, где уже есть хоть одна страница с текстом, останавливается и ничего не создаёт. С `--skip-text` её можно безопасно запускать на любом PDF, не думая, есть там текст или нет.

Другие режимы **не рекомендуются**:

- `--force-ocr` переводит в картинку даже страницы с нормальным текстом и заново распознаёт их. На тестовом файле размер вырос с 28 КБ до 156 КБ, текст стал «распознанным» вместо исходного.
- `--redo-ocr` предназначен для сканов со старым (плохим) текстовым слоем. На страницах с нормальным текстом он тоже изменил текст (на нашем тесте 1958 → 2140 символов). Применять только осознанно, для сканов с заведомо плохим встроенным распознаванием, и проверять результат.

Если текст в уже распознанном скане вас не устраивает (много ошибок), `--skip-text` его не исправит: это случай для `--redo-ocr` с ручной проверкой.

## Защита, если вы забыли прогнать файл через OCR

Перед ответом на вопрос Claude запускает `scripts/check-text-layer.sh`. Скрипт только читает: проверяет PDF вашей библиотеки (или выбранной коллекции) на наличие текста на страницах и сверяет статьи с индексом. Если нашёл проблему, Claude сообщит об этом до ответа: перечислит статьи без текста или не попавшие в индекс и подскажет, что делать.

Скрипт можно запустить и вручную из корня репозитория:

```bash
scripts/check-text-layer.sh                       # вся библиотека
scripts/check-text-layer.sh --collection "Название или ключ"   # одна коллекция
```

Что он сообщает:
- **PDF без текстового слоя** (0 страниц с текстом) и **PDF с текстом не на всех страницах** (без текста более 20% страниц);
- **PDF без родительской записи** (отдельные вложения, не привязанные ни к статье, ни к книге), в том числе точные копии друг друга;
- статьи **без PDF**, у которых в поиске только метаданные;
- вложения, **файла которых нет на диске**;
- статьи, **не попавшие в индекс** (добавлены после последней индексации).

Код выхода 0 — проблем нет, 1 — найдены. Скрипт считает страницей с текстом любую, где больше 50 символов; страницы с иллюстрациями без подписей ложных срабатываний не дают, пока таких страниц меньше 20%.

## Файл без родительской записи

Когда вы перетаскиваете PDF в Zotero, программа пытается сама найти метаданные (DOI, ISBN и т. п.) и создать запись-родителя. Для книг без DOI, для русских изданий и для текстов с плохо распознанными идентификаторами это часто не получается, и файл остаётся **отдельным вложением без записи**.

Типичные причины (по трём реальным файлам с eLIBRARY.RU):
- в файле нет DOI и ISBN (или ISBN записан необычными дефисами), а русские издания часто не находятся во внешних каталогах;
- первая страница PDF не титульная: это фрагмент журнала, где сверху лежит **конец другой статьи** (список литературы по высшей математике над статьёй по психологии) или середина текста с колонтитулом вместо заголовка, поэтому автораспознаванию не за что зацепиться;
- файл это вырезка нескольких страниц, без выходных данных.

Лучший способ избежать проблемы: не перетаскивать PDF с eLIBRARY.RU, а сохранять публикацию через расширение Zotero Connector с её страницы (так метаданные приходят с сайта, а PDF прикладывается к уже созданной записи; наличие подходящего «переводчика» для eLIBRARY.RU нужно проверить на вашей версии). Если и это не сработало, создайте запись вручную.

Такой файл поиск не увидит, даже если в нём отличный текст: индексатор берёт только статьи и книги, а вложения без родителя пропускает (проверено: `update-db` не находит их среди кандидатов и ничего не добавляет). Это касается и `.txt` (расшифровки, учебники): им тоже нужна карточка. Понять это по самому Zotero трудно, а `scripts/check-text-layer.sh` сообщает такие файлы отдельным пунктом.

Что делать:

1. В Zotero создать запись вручную (тип «Книга» или «Статья»: автор, название, издательство, год, ISBN; для расшифровок и учебников в `.txt` подойдёт тип «Документ» с названием и датой) и перетащить в неё файл. В Zotero также есть команда создания родительской записи для вложения в контекстном меню (название пункта зависит от версии).
2. Если вложение продублировано (скрипт пишет «точная копия»), оставить одно, остальные удалить.
3. `zotero-mcp update-db --fulltext`, затем `scripts/check-text-layer.sh`: пункта про вложения без родителя быть не должно.

## Что делать с уже загруженным сканом

1. В Zotero найти вложение, которое показал скрипт, и сохранить файл на диск (Show File).
2. Выполнить `ocrmypdf -l rus+eng --skip-text …` (см. выше).
3. Добавить распознанный файл к той же статье (перетащить на запись), а исходное вложение переместить в корзину Zotero.
4. `zotero-mcp update-db --fulltext`.
5. Повторить `scripts/check-text-layer.sh`.
