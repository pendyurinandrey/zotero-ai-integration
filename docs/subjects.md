# Папки предметов (работа вне репозитория)

Удобно вести каждый предмет в **своей папке**, которая никак не связана с этим репозиторием по расположению. В папке предмета лежат правила именно этого предмета (`CLAUDE.md`), реестр подготовки, готовые ответы. Общая часть (skill, скрипты поиска, разрешения) подключается из репозитория симлинками, а сам репозиторий Claude не меняет.

## Создание папки предмета

Создайте пустую папку предмета и выполните из корня репозитория:

```bash
scripts/new-subject.sh "/путь/к/папке/предмета" --collection "Название коллекции Zotero" --name "Название предмета"
```

Параметр `--dry-run` показывает, что будет создано, ничего не меняя. Скрипт безопасно запускать повторно: существующие файлы он не перезаписывает.

Что появляется в папке предмета:

| Файл | Что это |
|---|---|
| `.claude/skills/zotero-library` | симлинк на skill из репозитория (вместе со скриптами поиска) |
| `.claude/settings.json` | разрешения (копия из репозитория): читающие инструменты Zotero и команды скриптов без запросов; плюс запрет правки skill. Это обычный файл, а не симлинк |
| `.mcp.json` | подключение MCP-сервера `zotero` только для этой папки (абсолютный путь к `zotero-mcp`) |
| `CLAUDE.md` | заготовка правил предмета с названием коллекции (разделы TODO заполняете вы) |
| `.gitignore` | записи для перечисленного выше, если папка внутри git-репозитория |

Свои разрешения для предмета (например, запись файлов в `Экзамен/`) добавляйте в `.claude/settings.local.json`. Когда в репозитории меняется список разрешённых команд, обновите `settings.json` предмета командой `scripts/new-subject.sh … --refresh-settings` (файл пересоздаётся целиком, поэтому свои правила держите в `settings.local.json`).

## Первый запуск

Откройте Claude Code в папке предмета. Подтвердите доверие к папке и подключение MCP-сервера `zotero` (запрос появляется один раз на папку). После этого поиск, проверка библиотеки и ссылки работают так же, как в репозитории.

## Как устроены правила

- **Общие правила** (проверка Ollama, только чтение, формат ссылок по умолчанию, поиск по подтемам) лежат в skill.
- **Правила предмета** лежат в `CLAUDE.md` папки предмета: имя коллекции, как различать типы источников, режимы работы, формат ответов. Они имеют приоритет над форматом по умолчанию из skill.
- Импортировать `CLAUDE.md` репозитория в `CLAUDE.md` предмета не нужно: импорт вставляет только текст и **не подключает skills**, а текст репозиторного `CLAUDE.md` рассчитан на сессии внутри репозитория.

## Как Claude не меняет репозиторий

- Рабочая папка (папка предмета) вне репозитория, изменения вне неё по умолчанию требуют подтверждения.
- Через симлинк файлы skill видны внутри рабочей папки, поэтому в `settings.json` предмета стоит запрет `Edit` и `Write` на `.claude/skills/zotero-library/**`. Запреты приоритетнее разрешений. В самом репозитории этого запрета нет, чтобы не мешать править skill.
- Это не абсолютная граница для команд оболочки: правила Bash сопоставляются с текстом команды. Ориентируйтесь на то, что Claude запрашивает подтверждение на любую запись вне разрешённого.

## Ограничения

- **Перенос репозитория ломает симлинки** во всех папках предметов. Перенос самой папки предмета безопасен (симлинки абсолютные), но подтверждения доверия и MCP придётся пройти заново: они привязаны к пути.
- **Один skill на все предметы**: правка skill в репозитории меняет поведение сразу везде.
- Симлинки и `.mcp.json` содержат пути вашей машины: не синхронизируйте их между компьютерами и не коммитьте (`new-subject.sh` добавляет их в `.gitignore`).
- Каждый новый предмет нужно подключить скриптом: без него Claude не увидит skill.
- `settings.json` предмета это копия: при изменении списка разрешений в репозитории нужен `--refresh-settings`.

## Что проверено

На изолированной папке с пробелом и кириллицей в пути: скрипт создаёт всё перечисленное и безопасен при повторном запуске; все три скрипта поиска и проверки работают из такой папки через симлинки; `.mcp.json` распознаётся (ожидает вашего подтверждения). Не проверялась в интерактивной сессии загрузка skill через симлинк в папке предмета и срабатывание запретов `Edit`/`Write`: после создания первой папки это стоит проверить тестом T0 из [плана проверки](test-plan-psychology-collection.md).
