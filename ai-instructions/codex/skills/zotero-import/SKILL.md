# Реквизиты и файл импорта для Zotero

Возьми путь к папке из запроса пользователя, обычно это `fixed` после `$prepare-books`. Если путь не указан и его нельзя однозначно определить, уточни его. Запускай скрипт из корня репозитория. Путь с пробелами передавай в кавычках.

Задача: на каждый поддерживаемый файл папки одна запись с реквизитами по самому файлу, затем `.ris`, который пользователь импортирует в Zotero сам. В Zotero ничего не пиши (через MCP он только читается): импорт делает пользователь.

Правила:
- **Только то, что есть в файле** (титул, выходные данные, колонтитулы, «Для цитирования», «In: … Edited by»). Не угадывай: если автора, года или издательства в файле нет, оставь поле пустым и скажи об этом. Знание о книге «из памяти» не источник.
- Скрипт пропускает DOI и ISBN.
- Файлы папки не меняй и не переименовывай.

## 1. Подсказки по файлам

Файлы реквизитов и RIS лежат рядом с папкой файлов, а не внутри неё (иначе их добавят в Zotero вместе с книгами): для `…/Литература/fixed` это `…/Литература/zotero-import.json` и `…/Литература/zotero-import.ris`. Если пользователь указал другой путь вывода RIS, передай его вторым позиционным аргументом команде `build`.

```
scripts/make-ris.sh extract "<папка>" --skeleton "<родитель>/zotero-import.json"
```

Команда печатает по каждому файлу: число страниц, метаданные файла (часто пустые или служебные вроде «Microsoft Word - 4993.doc»: не верь им без титула), начало текста, строки с выходными данными со страниц 1–3 и последней, колонтитулы первой, второй и последней страниц (по ним видны печатные номера страниц и журнал). Если заготовка уже есть (повторный запуск), не перезаписывай её `--force` без спроса: в ней могут быть правки пользователя.

Чего не хватает, дочитай точечно: `pdftotext -f N -l N "<файл>" -`. Типичные места:
- журнал, год, том, номер: колонтитул первой страницы, «Для цитирования», блок «To cite this article», обложка репозитория;
- страницы статьи: печатные номера в колонтитулах первой и последней страницы PDF (диапазон = первая – последняя; если номер найден только на второй странице, отсчитай назад);
- книга: оборот титула (выходные данные, «Под ред.», издание, город: издательство, год);
- глава: «In: … Edited by …», название книги в колонтитуле.

Имена файлов на macOS бывают в разложенном виде Unicode (`й`, `ё`): открывай файл по имени из вывода `extract` или через glob, а не набирай заново.

## 2. Заполнение реквизитов

Заполни `zotero-import.json` (по записи на файл; поле `file` не меняй). Поля:

| поле | что писать |
|---|---|
| `type` | `journalArticle` статья; `bookSection` глава; `book` книга, учебник, сборник; `conferencePaper` доклад в сборнике; `presentation` доклад без сборника; `webpage` страница сайта; `thesis`, `report`, `magazineArticle`, `newspaperArticle`; `document` если ничего не подходит |
| `authors`, `editors` | списки `"Фамилия, Имя"` или `"Фамилия, И. О."` (как в источнике); у сборника обычно только `editors`; у главы `editors` это редакторы книги |
| `title` | название без лишних заглавных букв (как в источнике, но не капсом); опечатку титула исправить и сказать об этом |
| `container` | журнал; книга (для главы); сайт; конференция (для доклада). У `book` и `report` Zotero записывает его в поле «Серия»: для книги указывай только серию, если она есть, а не город или сборник |
| `edition`, `place`, `publisher`, `year`, `date` (`ГГГГ-ММ-ДД`), `volume`, `issue`, `pages` (`"224-246"`), `url`, `language` (`ru`, `en`) | если есть в файле |
| `note` | чем файл отличается от изданной версии: «авторская рукопись, номера страниц свои», «глава 1 (ознакомительный фрагмент)», «распечатка сайта», «реферат, не сама статья» |

Пустые поля можно удалить или оставить пустыми строками.

## 3. Дубли в Zotero (если Ollama запущен)

Проверь Ollama перед обращением к Zotero по инструкции [zotero-library](../zotero-library/SKILL.md). Если Ollama запущен и доступен читающий MCP-инструмент `zotero_search_items`, найди каждую работу по названию и покажи возможные совпадения. Если Ollama или MCP недоступны, сообщи, почему проверка пропущена, и продолжи локальную сборку RIS.

## 4. Таблица и сборка

Покажи таблицу: файл → тип → реквизиты кратко, отдельно пустые поля и заметки. Затем:

```
scripts/make-ris.sh build "<родитель>/zotero-import.json" "<родитель>/zotero-import.ris" --dir "<папка>"
```

Команда проверяет, что каждый файл папки описан ровно один раз, тип из списка, есть название, и предупреждает о записях без авторов, года или журнала. При ошибках RIS не записывается: исправь JSON и запусти снова. Существующий RIS перезаписывается только с `--force`.

## 5. Что сказать пользователю

1. Где лежат `zotero-import.ris` и `zotero-import.json` (в JSON можно поправить реквизиты и собрать RIS заново той же командой с `--force`).
2. Импорт: Zotero → «Файл → Импортировать… → Из файла» → выбрать `.ris`; отметить «Поместить импортированные коллекции и элементы в новую коллекцию» и «Копировать файлы в папку хранилища Zotero». Коллекция будет названа по имени файла: переименовать или перенести записи в нужную.
3. Что проверить: пустые поля, заметки, найденные дубли.
4. Дальше, как обычно: `zotero-mcp update-db --fulltext` (запускай только если пользователь просит) и `scripts/check-text-layer.sh --collection "Название"`.
